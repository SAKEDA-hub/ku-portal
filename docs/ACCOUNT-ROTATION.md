# Пакетная смена паролей

Эта операция предназначена для оператора хоста. Она заменяет пароли выбранных аккаунтов KU Portal, завершает их сеансы и требует задать постоянный пароль при следующем входе. Двухфакторная защита и остальные поля аккаунта сохраняются. Демо-аккаунты не меняются.

1. Убедитесь, что резервная копия базы создана, а новые пароли переданы пользователям через защищённый канал. На хосте должен быть задан `KU_DATA_ENCRYPTION_KEY` (64 шестнадцатеричных символа). Не помещайте новые пароли в историю команд, Git или обычный файл на диске.
2. Передайте в `node scripts/create-rotation-bundle.js <закрытый-каталог>` через stdin JSON вида `{"accounts":[{"userId":"std_1","password":"новый-длинный-пароль"}]}`. Источник stdin подготовьте в защищённой среде. Скрипт сохраняет только AES-GCM пакет с правами `0600` и выводит его путь, не пароли.
3. Сверьте список ID до создания пакета и количество записей после него. Команда `node scripts/stage-rotations.js <закрытый-каталог>` ставит пакеты в `data/portal-provision/`. **Если сервер запущен, он применит их в течение примерно пяти секунд; если остановлен — при следующем запуске.**
4. Проверьте журнал сервера и `data/account-rotation-batches.json` (в зашифрованном режиме он тоже зашифрован). Повторное предъявление пакета с тем же UUID не меняет пароли снова. Неприменённые поручения получают суффикс `.failed` и требуют ручного разбора.

Сервер удаляет свои прежние суточные копии `db-*.json` после успешного сохранения новых хешей. **Внешние копии**, сделанные `deploy/backup-pull.sh`, остаются на компьютере администратора; у них отдельный срок хранения. До истечения этого срока ограничьте доступ к ним. Восстановление копии, созданной до смены паролей, возвращает прежние хеши — после такого восстановления повторите смену паролей новым пакетом.
