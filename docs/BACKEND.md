# Бэкенд KU Portal

## Где работает сервер

Точка входа — `server.js`. Команда `node server.js` запускает один процесс Node.js для портала, KU Message и онлайн-экзамена. В конфигурации проекта этот процесс работает на alwaysdata в `~/ku-portal`. Этот же сервер отдаёт `public/` на основном адресе `https://ku-portal.alwaysdata.net/`. Для прежней копии интерфейса на GitHub Pages адрес API указан в `public/config.js`.

В истории Claude подключил сервер экзамена в коммите `ab52248`. В коммите `00eab13` Ilya с соавторством Claude вынес функции портала в `server/`. Ветка `backend-security` уже вошла в `main` через PR №22. В ней появились scrypt, ограничения на вход, атомарное сохранение JSON и ежедневные копии. [Подключение экзаменов](https://github.com/SAKEDA-hub/ku-portal/commit/ab52248) · [Перенос модулей](https://github.com/SAKEDA-hub/ku-portal/commit/00eab13) · [PR №22](https://github.com/SAKEDA-hub/ku-portal/pull/22)

Проверка исходной версии `0e8b828` показала, что общий снимок экзамена содержал учётные записи, пароли и результаты. Проверку личности и подсчёт баллов выполнял браузер. В портале права преподавателя выдавались при регистрации. В этой версии экзамен проверяет пользователя и его действия на сервере. Основное API портала сохранено, а выдачей доступа управляет оператор.

## Карта файлов

- `server.js` принимает HTTP-запросы. Здесь находятся регистрация, сеансы, TOTP, расписание, оценки, экспорт данных и выдача одноразового кода входа в мессенджер.
- `server/admin.js` — админ-панель (`/admin/`, API `/api/admin/*`) и применение поручений `reset-password`. `server/cleanup.js` удаляет пользователя со всеми следами и убирает демо-аккаунты из рабочей базы.
- `server/access.js` выбирает каталог данных и проверяет допуск к порталу. `scripts/access.js` — команды оператора. `server/audit.js` ведёт журнал изменений доступа и оценок.
- `server/security.js` отвечает за хеширование паролей, ограничения попыток и заголовки браузера. `server/http.js` читает JSON с ограничением в байтах и определяет адрес клиента.
- `server/messages.js` проверяет доступ к переписке, учебным каналам и вложениям. `server/clubs.js` обслуживает членство и заявки, `server/dorm.js` — обращения общежития. По действующей модели подтверждённые преподаватели администрируют клубы и общежитие. Оценку по предмету преподаватель ставит студенту группы, для которой этот предмет есть в его расписании.
- `server/ai.js` обслуживает публичный помощник сайта университета. Учебный корпус лежит в `data/ku-corpus.json.gz`. Адрес модели задаёт оператор через `LM_STUDIO_URL`, ключ — через `LM_STUDIO_API_KEY` в окружении процесса.
- `exam-sync/handler.js` отвечает за отдельный вход в экзамен, сессии и сохранение изменений. `exam-sync/model.js` определяет, какие записи доступны студенту и преподавателю. `exam-sync/grading.js` рассчитывает результат по шести типам заданий. Браузерная часть — `exam-sync/index.html` и `exam-sync/client.js`.
- `server/store.js` записывает базы через временный файл, `fsync` и переименование. `tests/` проверяет хранение, вход, миграцию и разграничение доступа.

## Первый запуск и обновление существующей установки

Из корня репозитория выполните:

```sh
node --test
node server.js
```

Локальный адрес — `http://127.0.0.1:3000`. Внешних npm-пакетов серверу не требуется. В рабочем режиме `DEMO=0` действует по умолчанию. На хостинге задайте `KU_DATA_DIR` абсолютным путём к постоянному закрытому каталогу. Для старой установки исходный путь — `~/ku-portal/data`. При переносе скопируйте весь каталог при остановленном процессе. Пустой новый каталог означает новую установку.

1. Перед обновлением действующего сайта приостановите автоматическое обновление, остановите процесс и сделайте закрытую копию всего каталога данных. Сохраните SHA текущего релиза.
2. Запустите новую версию с прежним каталогом. Старые сеансы портала завершатся. Подтвердите реальные аккаунты по списку группы и преподавателей. Общие бета-аккаунты в рабочем режиме заблокированы.
3. Для существующей базы экзамена сохраняются идентификаторы, работы и оценки. При миграции прежние пароли теряют силу. Выдайте новый пароль первому преподавателю командой `exam-reset` ниже. Он сможет сменить пароли студентов в интерфейсе. Копии старого файла и ранее открытые браузеры могли сохранить старые пароли. Если их использовали в других сервисах, владельцам следует сменить их и там. При наличии реальных ведомостей сверьте старые результаты с записями преподавателей.
4. Проверьте `/api/version`, вход обычного пользователя и преподавателя, затем возобновите выбранный способ обновления.

Для демонстрации запустите отдельный экземпляр. Он сохраняет всё в подкаталоге `demo/` и создаёт учебные аккаунты. В PowerShell:

```powershell
$env:DEMO = '1'
$env:IP = '127.0.0.1'
node server.js
```

В Linux эквивалентная команда — `DEMO=1 IP=127.0.0.1 node server.js`. Для рабочего запуска в той же оболочке PowerShell задайте `$env:DEMO = '0'`. Используйте разные браузерные профили или адреса для демонстрационной и рабочей установок.

## Выдача и отзыв доступа

**Портал и KU Message.** Пользователь регистрируется в портале и указывает роль и группу. Сервер возвращает `202` и показывает ожидание подтверждения. Войдите по SSH на хост, перейдите в каталог репозитория и используйте тот же `KU_DATA_DIR`, что и у сайта. Команды выводят внутренние ID, роль, имя, email, группу и текущий допуск.

```sh
node scripts/access.js list
node scripts/access.js approve std_42
node scripts/access.js revoke std_42
```

Здесь и далее ID и логины — примеры. До `approve` сверьте личность, роль и группу по университетскому списку. Веб-форма принимает заявление пользователя. Допуск привязан к конкретному ID, email, роли, группе и дате создания. Отзыв действует со следующего запроса, включая KU Message. После повторной выдачи допуска нужен новый вход. Пользователь может завершить свои сеансы в **Кабинет → Безопасность → Активные сеансы**.

**Группы преподавателя.** Преподаватель ставит оценки студентам только тех групп, которые за ним закрепил оператор или администратор (админ-панель → «Группы»); расписание для этого не нужно. Эти же группы дают личные чаты со студентами в KU Message. Экрана «Добавить занятие» в портале больше нет (API `/api/teacher/schedule` сохранён). Команда заменяет весь список, `list` показывает текущие группы преподавателей. Перезапуск не нужен.

```sh
node scripts/access.js groups tch_7 "ИСУ-26-2-а, БТ-26-1-а"
```

При первом запуске после обновления сервер один раз переносит в закрепления группы из текущего расписания каждого преподавателя. Новый преподаватель начинает без групп.

**Служебные роли.** Руководство клубами и общежитием не зависит от основной роли и выдаётся отдельно. Действует со следующего запроса, перезапуск не нужен.

```sh
node scripts/access.js role stf_3 manager                         # все клубы + общежитие
node scripts/access.js role stf_4 club-lead "volunteer,football"  # только эти клубы
node scripts/access.js role stf_5 dorm                            # администрация общежития
node scripts/access.js role stf_4 none                            # снять
```

ID клубов: `football`, `basketball`, `volunteer`, `debate`, `chess` и другие из списка клубов. Права хранятся в `access/perms-<sha256(ID)>.json`. Менеджер получает и `results` — учебную базу результатов.

**Учебная база результатов** (`/results/`, данные `results.json`, файлы заданий `results-files/`, копии `results-backups/`). Доступ только по праву `results` (менеджер, администратор или кому его выдали в админ-панели); преподавателям без этого права база закрыта. Вход из портала без пароля. Собственные логины базы работают только для учётных записей с ролью teacher. Снятие роли или допуска в портале закрывает базу со следующего запроса. Прежние имена `school.json`, `school-files/`, `school-backups/` переводятся автоматически при запуске.

**Онлайн-экзамен.** У сервиса отдельные логины. Чтобы создать первого преподавателя или восстановить существующий экзаменационный аккаунт, укажите его точный логин и роль:

```sh
node scripts/access.js exam-reset examiner teacher "Имя Фамилия"
```

Команда один раз показывает случайный пароль в терминале и кладёт поручение с его хешем в закрытый каталог. Передайте пароль пользователю по личному каналу. Перезапустите сайт в **Web → Sites**. Со следующего запуска работает новый пароль, после входа его можно изменить. При таком же логине требуется прежняя роль. Для студента используйте `student`. Чтобы закрыть доступ с сохранением работ, выполните `node scripts/access.js exam-disable examiner` и перезапустите сайт. Для повседневной работы преподаватель может создать студента или сменить его пароль из списка студентов экзамена.

Сеанс экзамена действует до 12 часов и сохраняется при перезапуске сервера (`exam-sessions.json` хранит только отпечатки токенов). Смена пароля и `exam-disable` завершают сеансы этого пользователя. Студент видит собственные работы и оценки. Ключи ответов остаются у сервера во время теста. После сдачи состав разбора зависит от настройки преподавателя. Сервер начинает отсчёт при открытии теста и даёт 15 секунд на доставку после истечения лимита. Поздняя отправка теста получает автоматический балл 0. Поздняя письменная работа сохраняется с отметкой для преподавателя. Выставление балла требует повторного ввода пароля преподавателя раз в час.

## Админ-панель и сброс пароля

Повседневное администрирование — в админ-панели `/admin/` (`admin/`, сервер `server/admin.js`, API `/api/admin/*`). Её видят подтверждённые пользователи с правом `admin` (`access/perms-*.json`). Первого администратора назначают с хоста:

```sh
node scripts/access.js role stf_1 admin          # менеджер + админ-панель
```

Панель: список пользователей и заявок, `approve`/`revoke`, группы преподавателя, служебные права, сброс пароля, удаление, скачивание копии базы. Сброс пароля, удаление и копия требуют повторного ввода пароля администратора, подтверждение действует час для этого сеанса. Защита от потери управления: администратор не может удалить себя, закрыть себе доступ или снять с себя право `admin`.

**Сброс пароля без панели:**

```sh
node scripts/access.js reset-password std_42          # новый временный пароль
node scripts/access.js reset-password std_42 --2fa    # то же + отключить 2FA (потерян телефон)
```

Команда печатает временный пароль и кладёт поручение с его хешем в `portal-provision/`. Работающий сервер применяет его в течение 5 секунд, остановленный — при запуске; перезапуск не нужен. Сервер держит базу в памяти, поэтому пароль меняется только так, а не правкой `db.json`. После сброса все сеансы пользователя завершаются, а при входе портал просит задать собственный пароль (`mustChangePassword`).

**Удаление пользователя** (`server/cleanup.js`, `scrubUsers`) убирает аккаунт, сеансы, допуск и права, личную переписку, членство и заявки в клубах, обращения в общежитие и вложения. Оценки студента удаляются вместе с ним. У преподавателя выставленные оценки и предметы остаются, расписание удаляется.

**Демо-аккаунты в рабочей базе.** При запуске в режиме `DEMO=0` сервер удаляет пользователей с отметкой `demo` и всё, что к ним привязано: предметы, расписание, оценки, переписку, участие в клубах. В журнал пишется строка `[cleanup] удалены демо-аккаунты: …`, в аудит — событие `portal.demo.purge`. Повторные запуски ничего не меняют.

## Восстановление пароля по почте

На экране входа есть ссылка «Забыли пароль?» (`public/auth.js`, сервер `server/recovery.js`). Пользователь вводит email, и подтверждённому пользователю уходит письмо со ссылкой `<KU_PUBLIC_URL>/#/reset/<код>`. Ссылка действует час и срабатывает один раз. В базе хранится только sha256 кода (`user.passReset`). Ответ сервера одинаков для любого адреса, поэтому по нему нельзя узнать, зарегистрирован ли email. После смены пароля все сеансы пользователя завершаются. Ограничения: 3 письма в час на адрес, 10 запросов в час с одного IP.

Письма отправляет системный `sendmail` (`server/mail.js`), на alwaysdata он есть. Переменные окружения: `KU_SENDMAIL` (путь, по умолчанию `/usr/sbin/sendmail`), `KU_MAIL_FROM` (отправитель, по умолчанию `noreply@ku-portal.alwaysdata.net`), `KU_PUBLIC_URL` (адрес сайта для ссылки, по умолчанию `https://ku-portal.alwaysdata.net`). Если `sendmail` нет, сайт честно отвечает, что восстановление недоступно. Если письмо не пришло, проверьте «Спам». Запасной путь — временный пароль из админ-панели.

## Копия базы вне сервера

Суточные копии в `backups/` лежат на том же сервере. Чтобы данные пережили потерю аккаунта хостинга, `deploy/backup-pull.sh` раз в день забирает весь каталог данных на компьютер администратора по SSH-ключу. Копии лежат в `~/Documents/KU-Portal/backups/ГГГГ-ММ-ДД/`, хранятся 60 дней, неизменённые файлы — жёсткие ссылки на прошлую копию. При ошибке появляется уведомление на рабочем столе. Установка на Linux с systemd:

```sh
install -m 755 deploy/backup-pull.sh ~/.local/bin/ku-portal-backup
# ~/.config/systemd/user/ku-portal-backup.service: [Service] Type=oneshot, ExecStart=%h/.local/bin/ku-portal-backup
# ~/.config/systemd/user/ku-portal-backup.timer:   [Timer] OnCalendar=*-*-* 12:00, OnStartupSec=10min, Persistent=true
systemctl --user enable --now ku-portal-backup.timer
systemctl --user start ku-portal-backup.service    # первая копия сразу
journalctl --user -u ku-portal-backup -n 20       # журнал копий
```

Если компьютер был выключен, пропущенная копия делается после включения. Разовая копия — кнопка «Скачать копию базы» в админ-панели. Восстановление: остановить автообновление и сайт, вернуть файлы в `~/ku-portal/data/` (FileZilla или `rsync`), запустить сайт.

## Куда пишутся данные

Пути ниже отсчитываются от `KU_DATA_DIR`, по умолчанию — от `data/` в репозитории. С одним рабочим каталогом должен работать один экземпляр сервера. Две копии процесса могут перезаписать изменения друг друга.

- `db.json` — пользователи портала, хеши паролей и токенов сеансов, настройки TOTP, оценки, расписание, переписка, заявки и метаданные вложений.
- `exam-sessions.json` — сеансы онлайн-экзамена: sha256 токена, ID пользователя, отпечаток хеша пароля и срок.
- `exam-sync.json` — пользователи экзамена, хеши паролей, тесты, комнаты, таймеры, сданные работы и баллы. Незавершённые ответы и черновики также хранятся в браузере пользователя. Рабочий клиент получает данные своего сеанса с сервера.
- `uploads/<id>` — содержимое вложения KU Message. Скачивание идёт через API с проверкой владельца или канала. Лимиты составляют 10 МиБ на файл, 100 МиБ на пользователя и 1 ГиБ на все вложения. Квота самого хостинга может быть меньше.
- `access/` — действующие допуски портала. `exam-provision/` — поручения операторов, которые экзаменационный сервер обрабатывает при старте. `portal-provision/` — поручения на сброс пароля портала (`reset-password`), сервер применяет их в течение 5 секунд.
- `audit/ГГГГ-ММ-ДД.jsonl` — события выдачи и отзыва доступа, смены пароля, изменения 2FA и выставления баллов. Запись содержит время UTC, вид события и внутренние идентификаторы. Для команд с хоста исполнитель обозначается `operator`. Для установления конкретного оператора используйте журнал SSH хостинга. Окно хранения — 30 календарных дней при последующей записи.
- `backups/db-ГГГГ-ММ-ДД.json` и `backups/exam-sync-ГГГГ-ММ-ДД.json` — снимок перед первой записью дня, до 14 файлов на каждую базу. При повреждении база восстанавливается из последней читаемой копии. При отсутствии пригодной копии и повреждении файла запуск останавливается.

Защищайте каталог и архивы правами сервисного пользователя. Новые приватные файлы на Linux создаются с правами `0600`, приватные подкаталоги — `0700`. Старые файлы, резервные архивы и Windows ACL проверяются отдельно. Хеши паролей, секреты TOTP, сообщения и работы делают резервные копии конфиденциальными. Каталог данных и резервные копии храните за пределами веб-каталогов. Администратор хоста имеет возможность читать и изменять эти файлы.

## Контроль версии, событий и восстановления

```sh
git status --short --branch
git log -1 --format="%h %an %s"
git show --stat HEAD
curl -fsS http://127.0.0.1:3000/api/version
```

Для размещённого сервера укажите его HTTPS-адрес. Поля `commit` и `startedAt` показывают версию и время запуска процесса. При старте строка `[startup]` в журнале также показывает фактический каталог и режим. Для проверки рабочей установки `GET /api/demo` должен возвращать `{"enabled":false}`. На alwaysdata журналы находятся в **Web → Sites → Logs**, в `~/admin/logs/sites/` и `~/admin/logs/http/`. Для задачи автообновления смотрите `~/admin/logs/jobs/`. [Документация alwaysdata о журналах](https://help.alwaysdata.com/en/docs/web-hosting/remote-access/admin-directory/)

Для просмотра последних событий на Linux задайте `KU_DATA_DIR` в SSH-сессии тем же путём, что и у сайта:

```sh
tail -n 30 "${KU_DATA_DIR:-$PWD/data}/audit/$(date -u +%F).jsonl"
```

Файл появляется при первом регистрируемом событии. Ошибки записи журнала помечаются `[audit]` в stderr. Ошибки копирования помечаются `[store]`. Ежедневные JSON-копии покрывают две базы. Для восстановления вложений, допусков и журнала делайте отдельную закрытую копию всего каталога данных на другом носителе.

Проверяйте восстановление в новом каталоге на отдельном локальном порту. Разверните туда копию, укажите её абсолютный путь через `KU_DATA_DIR`, запустите сервер и проверьте вход, оценку и скачивание известного вложения. Для возврата на рабочий хост сначала остановите работающий процесс, сохраните текущее состояние и сверьте допуски с более свежими отзывами из журнала. Перед возвратом публичного трафика проверьте версию и контрольные записи. Старый обработчик до этой миграции открывал полный снимок экзамена, поэтому такой код восстанавливайте только в закрытой среде.

## Настройки хостинга

- `IP` и `PORT` задают адрес и порт Node.js. На alwaysdata учитываются также `ALWAYSDATA_HTTPD_IP` и `ALWAYSDATA_HTTPD_PORT`. Внешний трафик принимается по HTTPS на прокси хостинга.
- `KU_TRUSTED_PROXIES` — IP-адреса или диапазоны CIDR прокси через запятую. На alwaysdata прокси подключается с `::1` и передаёт адрес посетителя в `X-Real-IP`: значение `::1`. Первая строка `[proxy]` в журнале сайта после запуска показывает адрес соединения и имена заголовков. При пустом значении лимиты используют адрес TCP-соединения. За общим прокси это один лимит на клиентов. Указывайте адреса после сверки с провайдером. Прокси должен выставлять надёжные крайние справа значения `X-Forwarded-For` и `X-Forwarded-Proto`.
- `PAGES_ORIGINS` задаёт точные origin интерфейса через запятую. Путь репозитория частью origin не является. Проекты с одним доменом GitHub Pages разделяют хранилище браузера. Для реальных данных используйте выделенный origin портала. При развёртывании форка укажите собственный адрес API и собственный origin интерфейса.
- При push в `main` workflow `.github/workflows/deploy.yml` проверяет синтаксис, запускает тесты и при настроенном SSH загружает весь портал на alwaysdata. Для SSH-деплоя нужны секреты `ALWAYSDATA_ACCOUNT`, `ALWAYSDATA_SSH_PASSWORD`, а для автоматического перезапуска — `ALWAYSDATA_API_TOKEN` и `ALWAYSDATA_SITE_ID`. Переменная Actions `ALWAYSDATA_KNOWN_HOSTS` содержит строку OpenSSH known_hosts с проверенным публичным ключом SSH-хоста. Отпечаток подтвердите у хостинга. После выкладки workflow сравнивает SHA работающего процесса с SHA сборки.
- Другой поддерживаемый способ обновления — задача alwaysdata, которая вызывает `deploy/alwaysdata-update.sh`. Она забирает `origin/main`, обновляет checkout только fast-forward и записывает `.restart`. Выберите один способ обновления бэкенда. Задача по расписанию работает независимо от результатов GitHub Actions.

## Вложения KU Message

`server/files.js` решает, какие файлы принимает `/api/files`: фото (PNG, JPG, GIF, WEBP) и документы (PDF, Word, Excel, PowerPoint, TXT, RTF, ODF, CSV). Архивы и любые исполняемые файлы отклоняются; содержимое должно совпадать с расширением (сигнатура файла). Фото браузер получает с типом картинки по `GET /api/files/<id>?inline=1`, остальное — только скачиванием. Файлы прикрепляются в личных чатах, на страницах предметов, в канале и чате клуба (`fileId` в `/api/clubs/post` и `/api/clubs/chat/send`).

## Помощь преподавателю

`server/help.js`, данные `db.help`. Преподаватель: `GET/POST /api/help`. Администратор: `GET /api/admin/help`, `POST /api/admin/help/reply` (`id`, `status`: `new|work|done|rejected`, `reply`) — как любое изменение в админ-панели, после подтверждения пароля. При удалении пользователя его обращения удаляются (`scrubUsers`).
