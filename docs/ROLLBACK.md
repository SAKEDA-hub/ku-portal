# Откат обновления

Обновление «Тема портала в онлайн-экзамене + рабочие настройки» влито в `main` одним merge-коммитом.
Состояние **до** обновления сохранено в ветке `backup/before-settings-update` (коммит `0f9b14f`).

## Способ 1. Render — быстрее всего (без git)

Render → сервис `ku-portal` → **Events** (или **Deploys**) → предыдущий успешный деплой → **Rollback**.
Сайт сразу вернётся к прошлой версии. Код в GitHub при этом не меняется: следующий `git push` в `main`
снова задеплоит новую версию — поэтому после проверки сделайте способ 2 или 3, если откат нужен навсегда.

## Способ 2. Отменить merge-коммит (история сохраняется — рекомендуется)

```bash
git checkout main && git pull
git log --merges --oneline -5          # найти «Merge: тема портала в онлайн-экзамене…»
git revert -m 1 <хеш-merge-коммита>
git push origin main                   # Render задеплоит откат автоматически
```

Вернуть обновление обратно: `git revert <хеш-коммита-отката>` и `git push`.

## Способ 3. Вернуть main точно к сохранённому состоянию

```bash
git checkout main && git pull
git reset --hard backup/before-settings-update   # или: git reset --hard 0f9b14f
git push --force-with-lease origin main
```

Перезаписывает историю `main` — используйте, только если способ 2 не подходит.

## Данные

Обновление добавляет в `data/db.json` новые поля пользователей (`settings`, `inbox`, `devices`, `totp`,
`passChangedAt`, `lastSeen`) и `sessMeta`. Старая версия их просто игнорирует — откат безопасен для данных.
На бесплатном тарифе Render база и так пересоздаётся при перезапуске.
