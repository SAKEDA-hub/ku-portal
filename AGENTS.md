# Инструкции для ИИ-агента (Codex, Claude, Cursor и т.п.)

Этот файл — для нейросети, которая будет дорабатывать проект. Пользователям сайта он не показывается.

## Главное правило

Исходный проект (stikech/ku-portal) не менять без необходимости. Не трогать: главную, расписание, оценки, рейтинг, вход и регистрацию, профиль. AI-помощник из портала убран по просьбе владельца; API `/api/ai/*` оставлен — им пользуется сайт университета (stikech.github.io). Дизайн задаётся CSS-переменными в `public/style.css` (`:root`) — новые экраны строить на них, свои цвета не вводить.

## Раздел «Экзамен» = вход в «Онлайн-экзамен»

Электронная очередь на спикинг из портала **удалена полностью** (экраны, API `/api/exam/*`, `/api/teacher/sessions*`, `/api/teacher/queue*`, SSE `/api/events`, демо-комнаты). Не восстанавливать её. Экзамены — тесты, writing, speaking-очередь, ведомость — живут в сервисе «Онлайн-экзамен».

- `public/app.js`, функция `viewExam()` — экран раздела «Экзамен» для студента и преподавателя: описание сервиса, проверка доступности, кнопка «Перейти к онлайн-экзамену» (с анимацией перехода) и «Открыть в новой вкладке». Маршруты `#/exam` и `#/t/queue` (а также старые `#/exam/...`, `#/t/room/...`) ведут сюда.
- `exam-sync/` — сервис «Онлайн-экзамен» из github.com/StephCurrysvg/exam-sync, встроенный в этот же сервер:
  - `exam-sync/handler.js` — сервер отдельного входа и синхронизации. `exam-sync/model.js` проверяет операции и выбирает данные по роли, `exam-sync/grading.js` проверяет ответы. Запросы к состоянию, изменениям и SSE требуют Bearer-сеанс экзамена. SSE сообщает номер версии.
  - `exam-sync/index.html` — интерфейс. Пути к API в нём относительные (`api/sync`), поэтому страница должна открываться по адресу с завершающим `/` (сервер сам перенаправляет `/exam-sync` → `/exam-sync/`);
  - данные — `data/exam-sync.json` (в `.gitignore`), в режиме `DEMO=1` отдельная база использует `exam-sync/seed.json`.
- Переход портал → экзамены: `/exam-sync/?from=ku-portal&back=<адрес портала>/#/exam`. Сайт экзаменов запоминает `back` на сессию вкладки, убирает параметры из адреса и показывает кнопку «KU Portal». `back` принимается только http(s) и только с того же хоста, хостов из `KU_HOSTS` (Render, GitHub Pages), localhost или локальной сети (`KU_HOSTS`, `kuHostOk` в `exam-sync/index.html`).
- Вход в онлайн-экзамен отдельный от портала (свои аккаунты exam-sync).
- Таймеры частей с лимитом (тест с `timeLimit`, письменная работа с `writing.minutes` > 0) — коллекция `timers` (синхронизируется, есть в `COLS` handler.js): время идёт и вне части (выход из теста, уход со страницы, закрытие вкладки, сброс прохождения). Выход → `awayAt`, преподавателю — уведомление и блок «Вышли во время экзамена» (`awayWidget`) с кнопкой «Остановить время» (`frozen`: время вне части не засчитывается). Функции: `tmStart/tmPresence/tmExpire/tmLeft`. Тесты без лимита — как раньше (выход = прерывание).
- Вызов на speaking у студента: `callAlert()` — окно «Вас вызывают на спикинг!» с кнопкой «Иду», мелодия `callChime()` (Web Audio, повтор до 3 раз до нажатия), вибрация, мигающий заголовок; системное уведомление с тегом `edu-call` (приложение Android играет для него свою мелодию), `window.kuDesktop.attention()` — мигание значка в приложении для ПК (если есть).
- После «Завершить» спикинга открывается `quickGrade()` — балл только за спикинг; тест и письмо проверяются позже на странице проверки.

## Темы и настройки

- Портал: `PALETTES`, `MODES`, `getPrefs()/setPref()` (localStorage `ku_prefs:<userId>`), `resolvedTheme()`, `applyTheme()` (вызывается в `route()`). Личный кабинет и настройки — **один экран** `viewProfile(section)` (`public/cabinet.js`) (`#/profile`, `#/profile/<раздел>`; старые `#/settings/*` ведут туда же): профиль + оглавление (`CAB_SECTIONS`) + все разделы настроек. В меню три пункта: Главная, Экзамен, Кабинет. Не возвращать плитки-ссылки на настройки и блок «Сервисы» в кабинет; «Экзамен» не дублировать в «Сервисах» главной. На `<html>`: `data-palette` (кроме `ku`), `data-mode="dark"`, `data-fs` (`sm`/`lg`/`xl` → `--fs`; все `font-size` в CSS — `calc(Npx * var(--fs))`, новые писать так же), `data-compact`, `data-still` (меньше анимации). Палитры и тёмный режим — блоки `:root[data-palette=…]` и `:root[data-mode="dark"]` в `public/style.css`; новые цвета — только через переменные (включая `--nav-bg`, `--tab-bg`, `--toast-bg` и т.п.). Ранний скрипт в `index.html` применяет тему до загрузки app.js.
- «Авто» = палитра программы: `user.program` — `'ku'` (по умолчанию) или `'arizona'`; задаётся при регистрации, отдаётся в `pubUser`. Демо-преподаватель — `arizona` (`DEMO_ACCOUNTS`, `syncDemoPrograms()`).
- Онлайн-экзамен: тема = цвет (`incampus` | `intl` | `emerald` | `violet` | `coral` | `graphite` | `pink` — `window.EDU_COLORS`) × режим (`auto` | `light` | `dark` | `system`). Итог в `data-theme`: `incampus`, `incampus-light`, `intl`, `intl-dark`; для палитр портала ещё `data-accent=<цвет>` (блоки `:root[data-accent…]` — меняют только акцент). Функции: `eduThemeOf()`/`eduPaint()` в раннем скрипте, `applyTheme()/setTheme()/setMode()`. Доступность в экзамене: `data-fs` (`sm`/`lg`/`xl` → `zoom` у `body`), `data-contrast`, `data-still`.
- Переход портал → экзамен передаёт всё оформление: `theme=` (`ku`→`incampus`, `arizona`→`intl`, остальные — как есть, `EXAM_COLOR` в app.js), `mode=` (всегда явно, иначе «Авто» в экзамене включит тёмный inCampus), `fs=`, `still=`. В экзамене это хранится на вкладку (sessionStorage `edu-theme-ku`, `edu-mode-ku`, `edu-fs-ku`, `edu-still-ku`); ручной выбор в настройках экзамена перебивает и удаляет значение из портала. Панель настроек — `accountSheet()` → `settingsHTML()`, личные настройки — `prefsGet()/prefSet()` (localStorage `edu-prefs:<id>`).
- **Все настройки рабочие — заглушек нет.** Портал: уведомления (`NOTIF`, опрос `/api/inbox` и `/api/exams/open` раз в 30 с; тост, звук `chime()`, уведомление браузера, фильтры по типам), безопасность (смена пароля, 2FA TOTP, оповещение о входе с нового устройства, активные сеансы), конфиденциальность (скрытие в рейтинге, статус «в сети», выгрузка данных), удаление аккаунта. Серверная часть — `server.js`: `/api/settings`, `/api/inbox[/read]`, `/api/auth/password`, `/api/2fa/{setup,enable,disable}`, `/api/sessions[/revoke]`, `/api/export`, `/api/account/delete`; входящие уведомления — `pushInbox()` (оценка, расписание, вход). Экзамен: размер текста, контраст, меньше анимации, звук/вибрация при вызове на speaking, уведомление об открытии экзамена (`notifyDiff()`), уведомления браузера, скрытие таймера (виден в последнюю минуту), отключение подтверждения отправки, смена пароля.
- Единственное недоступное — «Email-рассылка» в портале: на сервере нет отправки почты, переключатель заблокирован и так и подписан. Не выдавать его за работающий.
- Тестовые аккаунты портала: нельзя сменить пароль, включить 2FA и удалить (общие для всех).
- Адаптив портала: `--app-max` 440 → 720 (≥640px) → 1120 (≥1024px, верхнее меню `.bnav`, сетки `.dash` и `.cab` — личный кабинет).

## База данных и защита

Действующие пути, режимы, команды и процедуры описаны в [руководстве по бэкенду](docs/BACKEND.md). Сервер и CLI читают одинаковые `KU_DATA_DIR` и `DEMO`. Рабочие аккаунты портала требуют допуска оператора. Сеансы проверяют его при каждом запросе. Демо использует отдельный каталог. Секреты и действующие базы хранятся за пределами публикуемых файлов.

Для записи портала используйте `saveDB()`, для записи экзамена — сохранение проверенного набора изменений в `exam-sync/handler.js`. `server/store.js` отвечает за атомарную запись, 14 суточных копий и восстановление. Секретные поля экзаменов отфильтровываются перед выдачей браузеру. Тесты запускаются командой `node --test`.

## Админ-панель

`/admin/` (папка `admin/`, сервер `server/admin.js`, API `/api/admin/*`) — для подтверждённых пользователей с правом `admin` (`permsOf(u).admin`, назначает `node scripts/access.js role <ID> admin`). Плитка «Администрирование» на главной (`serviceTiles`). Опасные действия (`reset-password`, `delete`, `backup`) требуют `/api/admin/confirm` — пароль администратора, на час для сеанса. Сеансы пользователя завершать через `dropUserSessions(uid)`. Удаление пользователя и чистка демо-аккаунтов — `server/cleanup.js` (`scrubUsers`, `purgeDemo`). Новые данные с ID пользователя — добавлять в `scrubUsers`. Пароль портала с хоста меняется только поручением в `data/portal-provision/` (`scripts/access.js reset-password`), не правкой `db.json`. Онлайн-экзамен админ-панель не затрагивает.

## Сервисы (главная → «Сервисы»)

Плитки студента: Рейтинг, Расписание, Успеваемость, Клубы, Общежитие, Голосование. «KU Message» (`#/chats`, `viewMessage` в `public/message-launch.js`) и «Экзамен» (`#/exam`, `viewExam` в app.js) — только в верхнем меню: страница входа с кнопкой перехода (анимация `appTransition`) и «Открыть в новой вкладке». Карточек этих сервисов на главной нет — не возвращать. «Запись на зачёт», «AI-помощник», «Посещаемость», «Библиотека» убраны по просьбе владельца — не возвращать.
- **KU Message** — `ku-message/` (index.html, core.js, views.js, settings.js — настройки `#/settings/<раздел>` как окно настроек Telegram: профиль по центру (аватар, имя, email) и группы пунктов (цветной значок, название, значение, стрелка; группы разделены серой полосой) в колонке списка, раздел справа (заголовок секции цвета программы над карточкой, пояснение под ней), style.css; дизайн минималистичный, в духе Telegram: плоские поверхности, цвета поверхностей как в портале, без градиентных баннеров и свечений; узкая панель разделов слева (значок выбранного — в «таблетке» цвета программы; Чаты, Предметы, Клубы, у преподавателя — Ученики, Настройки; на телефоне — внизу), обои чата, пузыри с изогнутыми хвостиками, страница предмета — шапка и вкладки; мобильная вёрстка — блок `@media (max-width: 860px)`, десктоп без указания владельца не менять), раздаётся сервером под `/ku-message/` (`serveStatic`; старый `/connect/` перенаправляется), словарь — `public/i18n.js` (`../i18n.js`). Переход: `public/message-launch.js` → `POST /api/message/handoff` → одноразовый код (60 с) в адресе после `#` → `POST /api/message/redeem` (свой сеанс). Не класть токен в адрес. API — `server/messages.js`: страница предмета `s:<subjectId>` (одна на предмет для всех его групп; публикует только преподаватель предмета: лекции/практики/материалы и задания со сроком ≥ 7 дней), личный чат `d:<id1>:<id2>` (студент ↔ преподаватель его группы). Данные: `db.chat.{msgs,materials,tasks,reads}` (`db.chat.v = 3` — после переноса каналов «предмет + группа»), `db.files` + `data/uploads/<id>`. Не возвращать: каналы по группам, инструменты по направлениям, «Центр», статусы, просмотры, короткие задания; настроек мессенджера в Кабинете портала нет. Клубы в KU Message — только общение: `#/c/<id>` — канал (публикует только глава клуба, мероприятия с записью; ближайшее закреплено), `#/c/<id>/chat` — чат участников. Студент видит только свои клубы (без клубов раздел «Клубы» скрыт); заявок, карточек «подать заявку» и вкладки «Заявки» в мессенджере нет — всё это в портале. Портал открывает клуб сразу: `openMessage(newTab, 'c/<id>')` → параметр `open` в адресе перехода. Бета-аккаунты — `server/demo.js` (`/api/demo`); на входе в портал и в KU Message — блок «Бета-аккаунты» с входом в один клик.
- **Клубы** (`#/clubs`, `#/clubs/<id>` — та же страница с открытой карточкой клуба) — `public/campus.js`; сервер `server/clubs.js` (`/api/clubs*`, `db.clubs`). Одна страница без вкладок. Студент: профиль активности (кольцо часов и уровень Новичок → Легенда кампуса, плитки), «Мои клубы» (вклад в часах, кнопка «Чат клуба» → KU Message), «Найти клуб» (заявка / отозвать), активность за полгода, достижения, предстоящие записи, история. Преподаватель (глава клуба, отдельной роли нет): заявки на вступление, отметка неявки на прошедших мероприятиях, список клубов. Объявления, мероприятия и запись — не здесь, а в канале клуба в KU Message (не дублировать). Вступление по заявке: `/api/clubs/join` → `requests{uid: ts}`, решение главы — `/api/clubs/request` (уведомление `type: 'club'`). Канал (`posts[]`) и чат (`chat[]`) — только участникам, прочитанное — `db.clubReads`. У события `hours` и `absent[]`; данные профиля считаются на сервере (`activityOf`).
- **Общежитие** (`#/dorm`) — `public/campus.js`; сервер `server/dorm.js` (`/api/dorm*`, `db.dorm`). Администрация — роль `teacher`.
- **Голосование** (`#/voting`, плитка у всех) — `public/services.js`; сервер `server/polls.js` (`/api/polls*`, `db.polls`). Опросы создаёт, завершает и удаляет администратор (право `admin`). Адресаты: все, только студенты или выбранные группы. Голос анонимный: в опросе хранятся только счётчики и `sha256(salt + ID)` проголосовавших. Один голос, изменить нельзя. Результаты видны после своего голоса и в завершённых опросах.

## Языки (RU / KK / EN)

- `public/i18n.js` (подключён перед `app.js`): `t('русская строка', {vars})`, `tv(значение с сервера)`, `getLang()/setLang()` (localStorage `ku_lang`, настройка устройства — работает и на экране входа), `weekdayName()`, `fmtDay()`.
- Словарь `I18N`: ключ — русская строка, значение `[en, kk]`. Любой новый текст интерфейса оборачивать в `t()` и добавлять в словарь; пропуск видно в консоли (`[i18n] нет перевода`). Ошибки API и фиксированные ответы помощника переводятся по тому же словарю на клиенте — сервер по-прежнему отвечает по-русски.
- Пользовательские данные (ФИО, группы, свои названия предметов) не переводятся; встроенные предметы и типы занятий — переводятся.
- В онлайн-экзамен язык передаётся параметром `lang=` (sessionStorage `edu-lang-ku` на вкладку).

## Проверка после изменений

1. `node --check` для `server.js`, `server/*.js`, `public/*.js`, `ku-message/*.js`, `exam-sync/handler.js` проходит, `npm test` зелёный, `node server.js` запускается без ошибок.
2. В выделенном режиме `DEMO=1` вход под `teacher@demo.kz` / `1234` и `student@demo.kz` / `1234`: «Экзамен» сразу показывает вход в онлайн-экзамен, кнопка открывает `/exam-sync/`, там есть кнопка «KU Portal», она возвращает в портал.
3. Главная, расписание, оценки, рейтинг, профиль работают как раньше; сообщения, клубы, общежитие — под студентом и преподавателем.
4. Деплой. Сервер — alwaysdata (`https://ku-portal.alwaysdata.net`, код в `~/ku-portal`): задача по расписанию (каждые 5 мин) запускает `deploy/alwaysdata-update.sh` — `git fetch` + `git merge --ff-only origin/main` и запись файла `.restart`; `server.js` раз в 5 с проверяет `.restart`, сохраняет базу и завершается, alwaysdata запускает его заново. Веб и SSH на alwaysdata — разные машины (общий диск), поэтому `pkill` не работает. Слушать `IP`/`PORT` из окружения. `data/*.json` не в git и не трогаются. Node.js на alwaysdata раздаёт `public/` и API с одного адреса. Workflow `.github/workflows/deploy.yml` проверяет тесты и поддерживает SSH-выкладку всего проекта. Для прежней копии интерфейса на Pages сохраняются относительные пути, `API_BASE` из `public/config.js` и `PAGES_ORIGINS` в `server.js`. Новые ссылки и `fetch` в `public/` писать так же.
5. Откат — см. `docs/ROLLBACK.md` (ветки `backup/*`, `git revert -m 1 <merge>`, Render → Rollback).
