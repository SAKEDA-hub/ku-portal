# Инструкции для ИИ-агента (Codex, Claude, Cursor и т.п.)

Этот файл — для нейросети, которая будет дорабатывать проект. Пользователям сайта он не показывается.

## Главное правило

Исходный проект (stikech/ku-portal) не менять. Можно трогать только раздел «Электронная очередь» и всё, что подключается через описанные ниже точки расширения. Не трогать: главную, расписание, оценки, рейтинг, AI-помощника, вход и регистрацию, профиль. Дизайн задаётся CSS-переменными в `public/style.css` (`:root`) — новые экраны строить на них, свои цвета не вводить.

## Модули очереди: пробные тесты, грамматика, вокабуляр, редактор заданий

Планируется, что в разделе очереди появятся:
- пробные тесты;
- задания преподавателя по грамматике;
- задания по вокабуляру;
- редактор, в котором преподаватель создаёт эти задания.

Готовый код этих модулей нужно не встраивать в существующие функции, а подключать через реестр. Пока реестр пуст, на сайте ничего лишнего не выводится.

### 1. Фронтенд — `public/app.js`

Точка расширения: блок с комментарием «Точка расширения раздела «Электронная очередь»» (поиск по `QUEUE_MODULES`).

Зарегистрировать модуль:

```js
registerQueueModule({
  id: 'grammar',                 // латиница, [a-z][\w-]{1,30}; станет частью URL
  title: 'Грамматика',           // подпись кнопки
  icon: 'book',                  // ключ из объекта I (иконки в начале файла); можно добавить свою SVG-иконку туда
  roles: ['student', 'teacher'], // кому показывать кнопку
  disciplines: ['english'],      // в каких вкладках предметов показывать; null — во всех
  async render(root, ctx) {      // root — контейнер страницы; ctx — см. ниже
    root.innerHTML = '<div class="card">…</div>';
  },
});
```

Вызов `registerQueueModule(...)` ставить сразу после функции `viewQueueModule` (или в отдельном файле `public/modules/<id>.js`, подключённом в `public/index.html` после `app.js`).

Что происходит автоматически после регистрации:
- у студента на странице очереди (`paintExamList`) под фильтром уровней появляется кнопка модуля — через `moduleBar('student', qTab)`;
- у преподавателя на странице комнат (`renderTList`) — в контейнере `#tModules` через `moduleBar('teacher', tTab)`;
- маршруты уже есть в `route()`: студент — `#/exam/m/<id>?d=<discipline>`, преподаватель — `#/t/m/<id>?d=<discipline>`; оба вызывают `viewQueueModule(role, id)`, который рисует шапку «Назад» и вызывает `render`.

`ctx` в `render(root, ctx)`:

| Поле | Что это |
|---|---|
| `role` | `'student'` или `'teacher'` |
| `user` | текущий пользователь (`id`, `fio`, `group`, `role`) |
| `discipline` | id вкладки предмета (`english`, `math`, `politology`, `ecology`, `economics`, `it`) или `null` |
| `meta` | справочник `{ disciplines, levels }` — те же уровни серьёзности 1–4, что у комнат |
| `api(path, opts)` | запрос к серверу с токеном (`api('/modules/grammar/tasks')`) |
| `esc, svg, toast` | экранирование HTML, иконки, всплывающие сообщения |
| `onLive(fn)` | подписка на live-события (SSE); снимается автоматически при уходе со страницы |
| `lvlLabel, lvlBadge, discShort` | подписи уровня и предмета в едином стиле |

Редактор заданий — это модуль с `roles: ['teacher']`; прохождение — модуль с `roles: ['student']`. Можно сделать один модуль с ветвлением по `ctx.role`.

Вёрстка: использовать готовые классы — `card`, `btn pri`, `btn ghost`, `inp`, `lbl`, `row2`, `badge`, `lvb lvN`, `qtabs/qtab`, `lstrow`, `tx`. Мобильная ширина — до 440px.

### 2. Сервер — `server.js`

Точка расширения: массив `QUEUE_MODULE_ROUTES` (рядом с блоком SSE). Запросы на `/api/modules/...` после проверки авторизации проходят по этому массиву.

```js
QUEUE_MODULE_ROUTES.push(async (ctx) => {
  const { p, req, res, url, u, body, db, saveDB, nid, ok, bad, notifyUser, subjectForDiscipline } = ctx;
  if (p === '/api/modules/grammar/tasks' && req.method === 'GET') {
    db.moduleTasks = db.moduleTasks || [];
    ok(res, { items: db.moduleTasks.filter((t) => t.module === 'grammar') });
    return true;            // запрос обработан
  }
  return false;             // не наш путь — передать дальше
});
```

Правила:
- все пути модуля — только под `/api/modules/<id>/...`;
- пользователь уже авторизован (`u`), но роль проверять самим: создавать и редактировать задания — только `u.role === 'teacher'` и только свои (`teacherId === u.id`);
- данные хранить в новых коллекциях `db.json`, не меняя существующие: `db.moduleTasks` (задания и тесты), `db.moduleAttempts` (попытки студентов). Инициализировать лениво: `db.moduleTasks = db.moduleTasks || []`;
- идентификаторы — через `nid('mt')`, `nid('ma')`; после изменений — `saveDB()`;
- задание привязывать к предмету и уровню: `{ id, module, teacherId, discipline, level, title, items: [...], group, createdAt }`;
- студент видит задания своей группы (`!t.group || t.group === u.group`), без правильных ответов в ответе API — проверка на сервере;
- если результат должен попасть в «Успеваемость», писать в `db.grades` так же, как это делает приём спикинга: `{ id: nid('gr'), studentId, subjectId, teacherId, score, date, source: 'task:<id>' }`; `subjectId` брать через `subjectForDiscipline(teacherUser, discipline)` (есть в `ctx`; `teacherUser` — объект из `db.users`);
- уведомить студента о новом задании или проверке можно через `notifyUser(studentId, { type: 'module', module: '<id>', ... })` — событие придёт во фронтенд в `onLive`.

### 3. Проверка после встраивания

1. `node --check server.js` и `node --check public/app.js` проходят, `node server.js` запускается без ошибок.
2. Вход под `teacher@demo.kz` / `1234`: в разделе очереди появилась кнопка модуля, редактор создаёт задание.
3. Вход под `student@demo.kz` / `1234` в другом окне: кнопка модуля во вкладке нужного предмета, задание проходится, результат сохраняется.
4. Очередь работает как раньше: вызов, таймер ответа, приём с баллом.
5. Исходные разделы (главная, расписание, оценки, AI-помощник, профиль) не изменились.

## Как устроена очередь (для ориентира)

- Комната — запись в `db.examSessions` (`discipline`, `level` 1–4, `status` open/paused/closed, `slotMin` — минут на ответ, `warnSec` — за сколько секунд предупреждать).
- Запись студента — `db.queue`: `waiting → called → done | absent`; `startedAt` — момент запуска таймера ответа, `extraSec` — продление.
- Live-обновления: SSE `/api/events?ticket=…`, сервер шлёт только сигналы, данные клиент перечитывает через API.
